patched=2026-09-09T21:50:00+02:00

Architecture:
- acceptance-planner = WHAT must be true
- implementation-planner = HOW to decompose/sequence/resource-classify work
- orchestrator = execute plan/state machine, not project architect
- workers = implementation
- supervisor = enforcement
- reference-researcher = independent external truth when required
- acceptance-validator = verification

Included changes that were NOT separately applied from V2.5.5/5.6/5.7:
- reasoning-builder: dedicated 49,152 context / 4,096 output profile
- reasoning-builder writes primary artifact early
- retry budget per exact Dxxx deliverable, not per role
- maximum three attempts; no salvage IDs or fourth ledger entry
- generic core-capability/external-runtime boundary
- pre-validation IMPLEMENTATION_READY gate
- no validation/reference work when no runnable candidate exists

Implementation planner:
- dedicated 32,768 context / 4,096 output reasoning-capable profile
- writes .opencode-v2/IMPLEMENTATION_PLAN.md
- decomposes deliverables/dependencies/waves/file ownership
- estimates context class S/M/L/XL for future GPU-aware scheduling
- no web, no shell, no application edits

V2.6.8 control-plane updates:
- read-only `scripts/control-status.py` derives phase, leaf, dependency,
  attempt, and test state from filesystem artifacts
- TodoWrite is root-only UI mirroring; filesystem remains authoritative
- the supervisor atomically claims attempts before writing and enforces the cap
  in both live dispatch and persisted reconciliation
- live watchdog treats missing message parts as unknown, resets after tools,
  and uses the retained HTTP live-session discovery path
- planner wave assignments use canonical machine-readable lines
- required executable acceptance checks must exit zero before final PASS
- lessons use the current OpenCode2 session-create + prompt API in a separate
  learner session
