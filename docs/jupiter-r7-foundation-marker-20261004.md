# Jupiter R7 foundation READY marker normalization

Fresh original Jupiter R7 completed three productive foundation-research sessions and persisted `foundation_result: READY` with the expected partial-evidence handoff to later validation. The foundation file contained the completion marker exactly once as its last non-empty line, but the model wrapped that literal HTML-comment marker in a single pair of Markdown backticks. Because the gate validator required the completely bare line, `reference_gate_snapshot()` treated the foundation as incomplete and, after the third allowed session, changed the gate to `blocked`. Implementation planning never started.

The completion-marker validator now accepts exactly two equivalent terminal forms: the bare marker, or that exact marker wrapped once in Markdown inline-code backticks. It still requires exactly one raw marker occurrence and that normalized marker to be the final non-empty line. Fenced, embedded, duplicated, or non-final markers remain invalid. The reference-researcher prompt also now explicitly says not to wrap the final line in backticks or a code fence.

Regression coverage includes the exact R7 shape at the foundation attempt limit: three completed/productive sessions, `foundation_result: READY`, `result: PARTIAL`, and a backtick-wrapped final marker must produce gate state `ready`. Full Python suite: 640/640 PASS plus controller/query/sandbox/run-checks and Node plugin selftests. R7 also independently proved the new Stage-A terminal cleanup: no private R7 processes remained and port 58600 was closed after the driver stopped.
